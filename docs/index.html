Churn Predictor with Retention Recommendations

Executive summary of the modelling work and the retention-action layer.

Repository Dataset (Kaggle)

1. Problem statement

Identify the customers most likely to churn and tell a retention team what to do about each one. The data is the public Telco Customer Churn dataset: 7,043 customers, 19 account and service attributes, and a churn label with a 26.5% base rate. The deliverable is not just a score — it is a ranked list of the riskiest customers, each with the drivers behind their risk and a concrete recommended action, so the output can be worked top-down as an outreach queue.

2. Data and analysis

  • One data quirk, handled explicitly. TotalCharges is stored as text and is blank for the 11 customers with zero tenure; it is coerced to numeric with blanks set to 0, consistent with what zero tenure means.
  • Churn signal is tenure-dominated. Being new, on a month-to-month contract, on fiber internet, and paying by electronic check are the dominant churn correlates — a pattern that directly shaped how actions are assigned (finding 3 below).
  • The dataset is verified against its source. The tracked CSV is byte-identical to IBM’s published copy, so every number here is reproducible from a fresh clone with no download step.

3. Approach

Two scikit-learn models are trained on a stratified 80/20 split with a fixed seed: a Logistic Regression pipeline (one-hot categoricals, scaled numerics) and a HistGradientBoosting classifier as the capacity check. The logistic model does double duty: it ranks customers by churn probability and explains each prediction with per-customer contributions coef × (x − train_mean) — which for a linear model is exactly its SHAP decomposition, with no extra dependency. Each customer’s top-3 drivers are then passed through a small rule table (contract offer, onboarding program, fiber price review, autopay discount, support bundle) that picks one action per customer; the first driver with a matching rule wins. Every run appends its metrics to a shared results/metrics.jsonl log.

What we found

  1. The signal is mostly linear. Logistic Regression edges out gradient boosting on ROC-AUC (0.842 vs 0.833); the boosted model is marginally better on PR-AUC and top-decile recall. With no interaction effects worth the capacity, the interpretable model wins the job.
  2. Attribution for free. For a linear pipeline, coef × (x − mean) is the exact SHAP value, so each customer gets faithful drivers without adding an explainability dependency.
  3. Action-rule design had to be measured, not assumed. The first design matched rules in table-priority order across the top-3 drivers; measured on the real data it collapsed every top-decile customer to the same action, because month-to-month contracts appear in nearly everyone’s driver list. Matching on the strongest driver first restores discrimination. The failed variant is documented so it doesn’t come back.
  4. The list is skewed, honestly. 678 of 705 recommendations are the onboarding program — because low tenure genuinely dominates churn risk here. The per-customer drivers stay in the CSV so a retention team can still see the secondary signals.

Caveats: metrics come from a single fixed-seed split (no cross-validation at this scope); the action rules are heuristics, not measured treatment effects — nothing here estimates whether an action actually prevents churn (see future work); driver positivity is verified empirically on this dataset rather than enforced in code. Public dataset; no confidential data anywhere.

5. Future improvements

  • Uplift modelling — target the persuadable, not the doomed. Churn probability answers “who will leave”; the retention decision needs “who will stay because we intervened.” With campaign-outcome logs, a two-model or T-learner uplift setup ranks by treatment effect instead, and stops spending discounts on customers who would churn (or stay) regardless.
  • Expected-value ranking. Rank by churn probability × revenue at risk (monthly charges × expected remaining lifetime) rather than probability alone, so the queue maximizes retained revenue, not caught churners.
  • Survival analysis for the tenure signal. Tenure dominating a binary classifier is really a time-to-event pattern; a Cox or gradient-boosted survival model handles censoring properly and yields “churn within k months” curves that time the outreach, not just rank it.
  • Calibration before budgeting. Isotonic or Platt calibration on a validation fold, so “top decile” can become “everyone above a break-even probability” once action costs are known.
  • LLM-drafted outreach. The drivers and action per customer are exactly the grounding a language model needs to draft the personalized retention message itself, turning the CSV into ready-to-send outreach.
